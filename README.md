# 大樹 AI 競速場

國泰世華銀行 IT 部門尾牙主題的 Three.js 網頁彈珠競速抽獎。使用最新確認的概念圖設計：國泰綠／銀白智慧競技場、數位榕樹、上方賽道速報、Codex 擋板與 Credits 備援閘門。

## 開啟遊戲

Windows 已安裝 Node.js 時，雙擊 `開啟遊戲.cmd`，並保留啟動視窗。也可執行 `node scripts/serve.mjs`，開啟 http://127.0.0.1:4173/ 。所有網頁資源已打包在 dist，啟動後不需連線外部 CDN、OpenAI 或字體服務。請透過 HTTP 開啟，不能直接雙擊 index.html（Web Worker 需要）。

開發：`npm install`、`npm run dev`；正式建置：`npm run build`；核心測試：`npm test`。

### GitHub Pages 展示

推送到 `main` 後，GitHub Actions 會自動安裝套件、建置並發布到 Pages。此 repo 的網址格式為 `https://nekonyacer.github.io/marblerun/`。第一次請在 GitHub repo 的 **Settings → Pages** 將 **Build and deployment → Source** 設為 **GitHub Actions**；等 Actions 的 `Build and deploy GitHub Pages` 執行成功後即可用瀏覽器展示。觀看者不需要安裝 Node.js。

若自行從原始碼建置：需要 Node.js 22（含 npm）與網路下載 npm 套件，執行 `npm ci`、`npm run build`。本機建置會使用 `/` 路徑；GitHub Actions 會使用 `/marblerun/` 路徑。

## 操作

1. 使用預設 1,500 人示範賽，或按「匯入 Excel」。支援 .xlsx、.xls、.csv，可選工作表。
2. 名單可用「員工編號／姓名／部門」欄位；單欄姓名也可。缺少員編會自動產生。同名不合併，重複員編會拒絕匯入。可下載 Excel 範本。單場最多 1,500 人，檔案上限 10 MB。
3. 在「賽事設定」設定賽事名稱、得獎名額、畫面品質及是否排除歷史得獎者。
4. 按「賽道」選擇內建或自訂賽道；可直接調整機關、另存與匯出／匯入 JSON，資料僅存在 localStorage。比賽開始後鎖定賽道，需重新準備才能更換。
5. 按開始，倒數後進行競速。空白鍵開始／暫停／繼續；F 切換全螢幕。近景／廣角都跟隨領先群。切到其他分頁會自動暫停。
6. 足額過線後停止賽事，依過線順序顯示得獎者。可匯出 Excel 與 JSON 賽事紀錄。歷史得獎紀錄儲存在同一瀏覽器、同一網址的 localStorage，清除瀏覽器資料會移除。

匯入名單只在瀏覽器記憶體處理，重新載入需重新匯入。已完成賽事紀錄包含該場參賽名單，僅保留在本機瀏覽器或使用者下載的備份，不上傳伺服器。更換名單時請使用穩定且唯一的員編，才能正確排除歷史得獎者。示範賽與正式名單分別排除。

## 已實作機關

- Merge Conflict：連續旋轉的擋板，碰撞改變方向與速度。
- Credits Gate：每五秒切換左右開放通道，一側關閉、另一側開放，切換前播報預告。
- 500 Error／Hotfix：錯時升降的活塞擋板。
- 429 Rate Limit：四組間歇放行閘門。
- Timeout／Final Test：左右移動的撞擊球。
- Debug Pegs／Packet Router／Load Balancer：5 段錯列 peg 區，共 100 根有碰撞的柱子。

### 碰撞修正版本 v2

障礙物模型與碰撞共用 `src/obstacles.js` 的形狀、位置、方向及高度，包含中央立柱、分隔島、旋轉葉片、撞擊球和 peg。物理接觸改用與畫面一致的世界座標；人群碰撞解算後再次解決障礙物接觸，避免被其他彈珠擠進柱子。

邊框立柱已移至護欄外，場內中央立柱與分隔島仍有實際碰撞。閘門與活塞改為向上升起開放，高度連續變化並共用於碰撞判斷。模型底部隨坡面變形，避免穿地；路面標記與終點格使用獨立的深度偏移，避免共面閃爍。機關採深綠／琥珀警示條紋，提高投影時的可辨識度。

新賽事使用 `banyan-constrained-rolling-v2`。舊版 v1 引擎保留在 `src/legacy/`，重播工具依紀錄版本選用對應引擎，不會用新版規則重算舊結果。

速報由領先者變更、領先群實際碰撞及接近中的機關狀態產生。畫面差距是位置／速度換算的估計秒數，最終名次使用固定時間步模擬的過線時間。

## 模擬與效能範圍

這是賽道約束的滾動競速模型，不是 Rapier／Unity 的完整 3D 剛體模擬。彈珠沿 3D 賽道的縱向與橫向自由移動，包含重力近似、阻力、邊界、彈珠之間的空間雜湊碰撞與動態機關碰撞；目前不包含落軌、自由落體、跳台與旋轉剛體摩擦模型。

所有彈珠具有相同半徑、加速度、阻力和碰撞係數。Web Crypto 產生種子，以 Fisher–Yates 隨機分配起跑位置。不預先指定得獎者。不同起跑位置與路徑存在物理優勢，隨機位置讓每位同仁以相同程序參賽；此版本沒有經過統計等機率認證。

模擬在 Web Worker，以 90 Hz 固定步長處理全部參賽者；快照約 40 Hz。畫面以 InstancedMesh 繪製鏡頭範圍內的彈珠，使用約 55 ms 的同一時間軸插值顯示彈珠和機關，並避免插值造成的視覺穿透；背景參賽者持續模擬，鏡頭不影響結果。計時依模擬時間，硬體不足時可能慢於真實時間，保持結果一致。

## 調整賽道

賽道內容集中在 `src/course-config.js`，每筆資料可設定機關的 `id`、`s` 位置、`type`、`label`、固定動畫相位 `phase`、`enabled` 與 `params`。同一種元件能放置多次，各自覆寫參數。新增、停用、搬動機關不需修改模擬或繪圖程式。

12 種機關各自位於 `src/components/obstacles/`：7 種既有元件（包含終點）及 5 種新元件。每個模組包含預設參數、碰撞形狀、裝飾與動畫；物理和畫面使用同一份形狀。

完整參數表、設定範例及擴充步驟請見 [賽道編輯指南](docs/TRACK_EDITING.md)。可直接透過網頁「賽道」編輯、儲存並使用；原始碼設定檔仍可調整內建預設。

新增關卡：
- 需求變更轉向板：護欄相連的左右斜板與中央擺臂，將貼邊彈珠導回賽道。
- 設計交付蹺蹺板：平面往復擺動的平衡旋臂，改變兩側通道；沒有垂直跳躍。
- Code Review 分流器：兩段對向擺臂重新分配彈珠路線。
- UX Flow 卡片迷宮：有碰撞的圓角卡片錯列導流，阻斷兩側貼邊直通路徑。
- Sprint 截止閘門：三通道輪流放行，切換時保留開放通道，速報反映實際狀態。

新賽事使用 `banyan-constrained-rolling-v3`；JSON 紀錄保存完整賽道參數快照。舊 v1／v2 引擎保留供舊紀錄重播。調整後請執行碰撞、坡面幾何、機關導流與全員完賽測試。自由落體、跳台與多層交叉仍需擴充物理模型。

現場建議使用有硬體加速的桌面 Chrome／Edge。正式活動前必須在現場電腦、外接投影解析度測試 1,500 人賽事，依 FPS 選擇平衡／效能優先畫質。手機可操作，主要觀賽版面以桌面投影為準。概念圖的細緻光影與場景密度經過即時效能取捨；Logo 採用國泰世華銀行官網的正式中英文 SVG 字標，本地打包、不依賴外部連線；來源與使用說明見 [品牌素材說明](src/assets/README.md)。

## 稽核與重播

JSON 紀錄包含模型版本、種子、參賽者索引、名額、時間、得獎者與對應員編。保留本版本原始碼，可執行 `node scripts/replay.mjs <下載的紀錄.json>` 重算比對。此檔案是本機紀錄，不是數位簽章或防竄改憑證。模型改版後應保留原版本重播工具。

## 驗證

自動化測試涵蓋名單解析、同名及重複員編、種子可重現性、閘門輪替、全體持續模擬，以及 1,500 人完整產生五名得獎者。實際瀏覽器另驗證 1,500 人完整賽事、Excel 結果下載與讀回、多工作表匯入、空白工作表錯誤與名額設定。

## GitHub Pages

保持純靜態部署，不需要後端。執行 `npm ci`、`npm run build` 後，發布 `dist/`。相對資源路徑支援 GitHub 專案子目錄；亦附 `.github/workflows/pages.yml`，在 GitHub Settings → Pages 將 Source 設為 GitHub Actions，再推送 main 即可部署。賽道存檔不會自動跨瀏覽器或跨網址同步，請匯出 JSON 後在目的瀏覽器匯入。

## 未來城市場景

賽道加入青綠光流導引線，周邊改為銀白高樓、空中花園與全像圖標。視覺元件集中在 `src/visuals/`：`circuit-track.js`（路面與護欄）、`future-city.js`（城市與綠化）、`holograms.js`（浮空圖標與投影光束）。使用批次繪製、共用材質與靜態圖集，未加入 Bloom、即時陰影或額外動態光源。

「效能優先」保留路線與圖標，減少遠景光飾、投影光束及彈珠細分；「平衡」與「細緻」提供較完整細節。系統減少動態效果偏好會停止裝飾光流與懸浮動畫。這些選項不影響碰撞、名次或賽道存檔，仍可純靜態部署。
