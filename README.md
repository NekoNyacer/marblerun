# 大樹 AI 競速場

國泰 IT 部門尾牙主題的 Three.js 網頁彈珠競速抽獎。使用最新確認的概念圖設計：國泰綠／銀白智慧競技場、數位榕樹、上方賽道速報、Codex 擋板與 Credits 備援閘門。

## 開啟遊戲

Windows 已安裝 Node.js 時，雙擊 `開啟遊戲.cmd`，並保留啟動視窗。也可執行 `node scripts/serve.mjs`，開啟 http://127.0.0.1:4173/ 。所有網頁資源已打包在 dist，啟動後不需連線外部 CDN、OpenAI 或字體服務。請透過 HTTP 開啟，不能直接雙擊 index.html（Web Worker 需要）。

開發：`npm install`、`npm run dev`；正式建置：`npm run build`；核心測試：`npm test`。

## 操作

1. 使用預設 1,500 人示範賽，或按「匯入 Excel」。支援 .xlsx、.xls、.csv，可選工作表。
2. 名單可用「員工編號／姓名／部門」欄位；單欄姓名也可。缺少員編會自動產生。同名不合併，重複員編會拒絕匯入。可下載 Excel 範本。單場最多 1,500 人，檔案上限 10 MB。
3. 在「賽事設定」設定賽事名稱、得獎名額、畫面品質及是否排除歷史得獎者。
4. 按「賽道」選擇內建或自訂賽道；可直接調整機關、另存與匯出／匯入 JSON，資料僅存在 localStorage。比賽開始後鎖定賽道，需重新準備才能更換。
5. 按開始，倒數後進行競速。空白鍵開始／暫停／繼續；F 切換全螢幕。近景／廣角都跟隨領先群。切到其他分頁會自動暫停。
6. 足額過線後停止賽事，依過線順序顯示得獎者。可匯出 Excel 與 JSON 賽事紀錄。歷史得獎紀錄儲存在同一瀏覽器、同一網址的 localStorage，清除瀏覽器資料會移除。

匯入名單只在瀏覽器記憶體處理，重新載入需重新匯入。已完成賽事紀錄包含該場參賽名單，僅保留在本機瀏覽器或使用者下載的備份，不上傳伺服器。更換名單時請使用穩定且唯一的員編，才能正確排除歷史得獎者。示範賽與正式名單分別排除。

## 已實作機關

- Merge Conflict：連續旋轉的擋板，碰撞改變方向與速度。
- Credits Gate：每五秒切換左右開放通道，一側關閉、另一側開放，切換前播報預告。
- 500 Error／Hotfix：錯時升降的活塞擋板。
- 429 Rate Limit：四組間歇放行閘門。
- Timeout／Final Test：左右移動的撞擊球。
- Debug Pegs／Packet Router／Load Balancer：5 段錯列 peg 區，共 100 根有碰撞的柱子。

### 碰撞修正版本 v2

障礙物模型與碰撞共用 `src/obstacles.js` 的形狀、位置、方向及高度，包含中央立柱、分隔島、旋轉葉片、撞擊球和 peg。物理接觸改用與畫面一致的世界座標；人群碰撞解算後再次解決障礙物接觸，避免被其他彈珠擠進柱子。

邊框立柱已移至護欄外，場內中央立柱與分隔島仍有實際碰撞。閘門與活塞改為向上升起開放，高度連續變化並共用於碰撞判斷。模型底部隨坡面變形，避免穿地；路面標記與終點格使用獨立的深度偏移，避免共面閃爍。機關採深綠／琥珀警示條紋，提高投影時的可辨識度。

v2 當時的新賽事使用 `banyan-constrained-rolling-v2`。舊版 v1 引擎保留在 `src/legacy/`，重播工具依紀錄版本選用對應引擎，不會用新版規則重算舊結果。

速報由領先者變更、領先群實際碰撞及接近中的機關狀態產生。畫面差距是位置／速度換算的估計秒數，最終名次使用固定時間步模擬的過線時間。

## 模擬與效能範圍

主賽道使用賽道約束的滾動競速模型：彈珠沿賽道縱向與橫向移動，包含重力近似、阻力、邊界、空間雜湊球間碰撞與動態機關碰撞。「電梯故障・加班沙漏」改用局部 3D 球體接觸解算，具有垂直速度、重力、移動表面接觸、漏斗摩擦、自由落體與落地。全賽道尚未改為通用 3D 剛體引擎，也沒有完整旋轉剛體、落軌或多層交叉模型。

所有彈珠具有相同半徑、加速度、阻力和碰撞係數。Web Crypto 產生種子，以 Fisher–Yates 隨機分配起跑位置。不預先指定得獎者。不同起跑位置與路徑存在物理優勢，隨機位置讓每位同仁以相同程序參賽；此版本沒有經過統計等機率認證。

模擬在 Web Worker，以 90 Hz 固定步長處理全部參賽者；樓梯與沙漏在每步內執行 4 次 3D 物理子步，使用 `g = 9.81 m/s²`；快照約 40 Hz。畫面以 InstancedMesh 繪製鏡頭範圍內的彈珠，使用約 55 ms 的同一時間軸插值顯示彈珠和機關，並避免插值造成的視覺穿透；背景參賽者持續模擬，鏡頭不影響結果。計時依模擬時間，硬體不足時可能慢於真實時間，保持結果一致。

## 調整賽道

主辦方可在網頁「賽道」直接點選 12 個固定位置，更換機關或保留空白直線，儲存後供本機使用，或匯出 JSON 移轉。8 條內建賽道由 `src/course-library.js` 與 `src/course-slots.js` 定義。開發用基準賽道保留在 `src/course-config.js`。

機關元件各自位於 `src/components/obstacles/`；已下架的舊元件保留給先前存檔和紀錄相容使用。每個模組包含預設參數、碰撞形狀、裝飾與動畫；一般機關共用形狀描述，樓梯與沙漏的 3D 接觸面及顯示硬體則共用 `src/overtime-geometry.js`。

視覺編輯、舊賽道相容及元件擴充請見 [賽道編輯指南](docs/TRACK_EDITING.md)。可直接透過網頁「賽道」編輯、儲存並使用；原始碼設定檔仍可調整內建預設。

新增關卡：
- 需求變更轉向板：護欄相連的左右斜板與中央擺臂，將貼邊彈珠導回賽道。
- 設計交付蹺蹺板：平面往復擺動的平衡旋臂，改變兩側通道；沒有垂直跳躍。
- Code Review 回擊推板：雙側自動拍擊把彈珠往回打，中央縫隙和回板空檔可通行。
- UX Flow 卡片迷宮：有碰撞的圓角卡片錯列導流，阻斷兩側貼邊直通路徑。
- Sprint 截止閘門：三通道輪流放行，切換時保留開放通道，速報反映實際狀態。

新賽事使用 `banyan-constrained-rolling-v6`；JSON 紀錄保存完整賽道設定。舊 v1／v2／v3／v4／v5 引擎保留供舊紀錄重播；v5 的原有引導路徑位於 `src/legacy/v5/`。調整後請執行碰撞、坡面幾何、機關導流、局部 3D 物理與全員完賽測試。

### 樓梯與沙漏的 v6 物理

階梯的實心立面、斜頂、升降位置與接觸面速度共同決定彈珠能否向上通過。升降表面會傳遞速度；彈珠可撞上立面、離開表面或因其他彈珠碰撞改變路徑。高架平台及收斂導流欄接到靜止沙漏，球在漏斗面受到重力、法向接觸及摩擦作用，經喉口及下漏斗後自由落下，保留速度落回主賽道。機關內球間碰撞使用 3D 空間雜湊；`stage` 只回報所在區域，不指定位置或放行時間。

階梯採用 2.2 的機械傳動比，馬達最大加速度為 `4.4 m/s²`；設定的 `period` 是要求週期，實際週期會受加速度上限限制。舊存檔的 `orbit` 欄位改為調整漏斗摩擦阻力，數值較大代表阻力較小，並非指定轉圈秒數。各項尺寸與高度、階梯行程及有效週期由 `src/overtime-geometry.js` 同時供物理和繪圖使用。

現場建議使用有硬體加速的桌面 Chrome／Edge。正式活動前必須在現場電腦、外接投影解析度測試 1,500 人賽事，依 FPS 選擇平衡／效能優先畫質。手機可操作，主要觀賽版面以桌面投影為準。概念圖的細緻光影與場景密度經過即時效能取捨；頁首採用國泰世華銀行中英文 SVG 品牌素材，文字保持完整排版。

## 稽核與重播

JSON 紀錄包含模型版本、種子、參賽者索引、名額、時間、得獎者與對應員編。保留本版本原始碼，可執行 `node scripts/replay.mjs <下載的紀錄.json>` 重算比對。此檔案是本機紀錄，不是數位簽章或防竄改憑證。模型改版後應保留原版本重播工具。

## 驗證

測試套件包含名單解析、同名及重複員編、種子可重現性、閘門輪替、全體持續模擬與 1,500 人賽事測試。v6 另有樓梯／沙漏接觸、自由落體、動量、球間碰撞、共享幾何及 v5 舊紀錄重播測試；以 `npm test` 檢查目前結果。本次 v6 回歸測試共 80 項通過，包含 1,500 人全員通過樓梯／沙漏並完賽（種子 82，209.74 模擬秒）、100 人逐步重跑結果一致，以及 4 組合法參數邊界。瀏覽器另以含兩組新機關的「電梯故障・加班沙漏」100 人示範賽完成前三名，無程式錯誤；GPU 效能及投影解析度仍需在活動電腦驗收。Excel 結果下載與讀回、多工作表匯入、空白工作表錯誤及名額設定亦應納入現場驗收。

## GitHub Pages

保持純靜態部署，不需要後端。執行 `npm ci`、`npm run build` 後，發布 `dist/`。相對資源路徑支援 GitHub 專案子目錄；亦附 `.github/workflows/pages.yml`，在 GitHub Settings → Pages 將 Source 設為 GitHub Actions，再推送 main 即可部署。賽道存檔不會自動跨瀏覽器或跨網址同步，請匯出 JSON 後在目的瀏覽器匯入。

## 未來城市場景

賽道加入青綠光流導引線，周邊改為銀白高樓、空中花園與全像圖標。視覺元件集中在 `src/visuals/`：`circuit-track.js`（路面與護欄）、`future-city.js`（城市與綠化）、`holograms.js`（浮空圖標與投影光束）。使用批次繪製、共用材質與靜態圖集，未加入 Bloom、即時陰影或額外動態光源。

「效能優先」保留路線與圖標，減少遠景光飾、投影光束及彈珠細分；「平衡」與「細緻」提供較完整細節。系統減少動態效果偏好會停止裝飾光流與懸浮動畫。這些選項不影響碰撞、名次或賽道存檔，仍可純靜態部署。

## 新機關與賽道

- 418 茶壺在賽道上交替升起兩組實際障礙；UX Flow 迷宮增加多道交錯擋板。
- 「電梯故障・加班沙漏」是一組機關：交替升降的實心階梯透過接觸帶動彈珠爬高，收斂平台連接靜止漏斗，重力、摩擦與球間碰撞決定流動，最後自由落回賽道；機關內使用局部 3D 球體解算。
- 404、Node.js、Java 與舊版 .NET 漏洞已從內建賽道及新增機關選單下架；已儲存的舊賽道仍能讀取、使用或匯出；新賽事會提示並跳過下架機關，也可在編輯器替換，或明確轉換為新副本。
- 8 條內建賽道與 12 個固定位置的視覺化編輯器，賽道以 localStorage 保存，JSON 可跨瀏覽器移轉。
- 「音樂與音效」可開啟原創合成派對配樂；暫停或切到其他分頁會停止播放。音樂說明見 [docs/MUSIC.md](docs/MUSIC.md)。
