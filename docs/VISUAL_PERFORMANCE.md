# 未來城市場景效能紀錄

2026-10-28，以同一個 Chromium／SwiftShader 軟體繪圖環境，比較 1280×800、DPR 1、1,500 人起跑畫面。載入後略過前三幀，取後續 15 幀。未啟動物理賽事；這份紀錄比較場景繪製成本，不代表現場硬體的 FPS。

| 指標 | 原場景 | 未來城市（簡化光照後） |
| --- | ---: | ---: |
| 每幀繪製次數 | 450 | 141 |
| 幀時間中位數 | 566.5 ms | 366.7 ms |
| 幀時間平均值 | 560.0 ms | 374.4 ms |
| 幾何資源數 | 450 | 138 |
| 繪製三角形 | 141,662 | 140,536 |
| 可見彈珠 | 257 | 290 |

原場景設定為效能優先，新版為平衡；在 DPR 1 時，原版兩個選項的解析度和模型細節相同。新版平衡採 16×10 彈珠細分，細緻保留 18×12；效能優先使用 12×8。兩次隨機種子不同，鏡頭構圖也因本次調整略有不同，因此這是固定尺寸、同等參賽量的代表場景比較，並非每一幀完全相同的微型基準。

第一輪全 PBR 城市幀時間中位數達 783.3 ms，未符合要求；改用遠景／路面的輕量漫反射材質、減少樹冠細分後降到上表數值。最後補足近景全像圖標後仍維持同樣繪製批次，沒有新增動態光源、陰影或全螢幕後製。

- 路面與護欄：9 個批次，光流於共用路面材質中計算。
- 城市：10 個批次，建物、樹木與公園使用 InstancedMesh；窗格為材質圖樣。
- 全像投影：1 張 1024×512 圖集，3 個批次；效能優先僅保留圖標。
- 終點標記：由 40 個路面小物件合併成 2 個批次。
- 減少動態效果偏好會凍結裝飾動畫。

自動化測試限制城市批次／三角形預算，並驗證靜態城市不會逐幀上傳 instance buffer。桌面與 390px 手機畫面均檢查過；正式活動仍應以現場 GPU、投影解析度及完整 1,500 人動態賽事驗收。
