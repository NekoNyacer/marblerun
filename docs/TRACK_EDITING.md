# 編輯賽道與機關

按頁首「賽道」，選一條內建主題賽道，就能直接開賽。主辦方也能點選路線上的任一站，再從機關圖示中挑選這一站要放什麼。選「空白直線」即可留下一段衝刺空間。

所有新賽道共用 12 個固定位置：`26, 59, 92, 125, 158, 191, 224, 257, 290, 323, 356, 389`。終點固定在 `430`。編輯器已設定位置、大小與運作方式，不需要輸入數字或 JSON 參數。位置按鈕可用鍵盤上下方向鍵切換。

## 內建主題

- 未來城市・全機關嘉年華：一次體驗所有新機關。
- 經典 IT 賽道：碰撞柱、升降障礙與計時閘門。
- 輕量暖身賽道：六站機關，保留較多衝刺空間。
- HTTP 狀態碼大亂鬥：500、429 與 418 輪番上場。
- 電梯故障・加班沙漏：樓梯與加班沙漏搭配交錯擋板、茶壺與閘門。
- Code Review 太空彈珠台：多組雙側回擊推板，搭配旋轉板與撞球。
- 需求又改了・設計衝刺：需求變更、UX 迷宮與設計交付。
- 落後才有機會・逆轉大道：樓梯、沙漏與碰撞機關反覆改寫領先順序。

418 茶壺前有兩組交替由地面升起的障礙柱。樓梯與加班沙漏是一組機關，佔用一個位置；彈珠撞上升降階梯的實心立面與斜頂，受移動表面接觸帶動登高，再由收斂平台及導流欄進入靜止沙漏。重力、漏斗摩擦與球間碰撞決定流動，彈珠通過喉口、下漏斗後自由落回賽道。

## 儲存、匯入與舊賽道

編輯名稱或機關後，按「儲存並使用」套用本場；「另存新賽道」建立個人副本。內建賽道保留不變，修改後會存成個人賽道。比賽倒數、進行或暫停期間，請先重新準備賽事才能切換。

舊版自訂賽道的原始配置仍可匯出，原本的參數與停用機關會完整保留。開始比賽時，已下架的 404、Node.js、Java 與舊版沙漏機關會自動略過；其他機關照常運作。編輯器會顯示原配置；按「建立固定位置副本」並確認後，才會建立新的 12 站版本。超過 12 個機關時會依原本順序均勻保留 12 個，使用各機關預設設定，已下架的 404、Node.js、Java 與舊沙漏機關在轉換副本時會略過；略過的總數、其中已下架機關數和停用機關數都會在確認訊息中顯示。原賽道不會被覆寫。舊版固定位置賽道若仍包含已下架機關，編輯器會標示「已下架」及比賽時將略過；點選該站即可換成目前機關。

每個網站網址下的 localStorage 保存最多 50 條個人賽道與上次選擇。「匯出 JSON」下載目前草稿；在另一個瀏覽器或部署網址按「匯入賽道 JSON」，即可建立獨立存檔。匯入不會覆蓋原有存檔。檔案上限 512 KB，仍支援原有 `format: "marblerun-course"`、`version: 1` 格式及最多 128 個機關。得獎紀錄與賽道 JSON 用途不同。

localStorage 不會跨瀏覽器或跨網址同步；清除網站資料也會刪除個人賽道。儲存失敗時草稿會保留，可先匯出備份。

## 開發者：獨立機關元件

`src/course-slots.js` 定義固定位置、編輯器說明與機關圖示資料。`src/course-library.js` 定義可選的內建主題。`src/course-config.js` 保留自由配置的原始範例。

所有機關模組位於 `src/components/obstacles/`，由 `index.js` 註冊。每個元件擁有 `type`、`label`、`defaults`、`build`，以及可選的 `decorate`、`update`、`notice`。

| type | 機關 |
| --- | --- |
| `gate` | Credits 雙通道交替閘門 |
| `rotor` | Merge Conflict 旋轉擋板 |
| `rate` | 429 Rate Limit 限流閘門 |
| `error` | 500 Error 升降障礙 |
| `pendulum` | Timeout 擺錘 |
| `pegs` | Debug 碰撞柱陣 |
| `scope-change` | 需求變更轉向板 |
| `sprint` | Sprint 截止閘門 |
| `ux-flow` | UX 卡片迷宮 |
| `handoff` | 設計交付擺臂 |
| `code-review` | Code Review 雙側回擊推板 |
| `teapot` | 418 茶壺升降障礙 |
| `overtime-stairs` | 升降樓梯與加班沙漏 |
| `finish` | Deploy 終點 |

一般機關由 `build(ctx, params, t, phase)` 定義實體形狀，繪圖與碰撞共用其結果。`ctx.box(id,x,ds,y,h,w,d,props)` 建立長方體；`ctx.add` 支援圓柱與球體。形狀的種類、數量、尺寸與 ID 在運行中須保持穩定；動態碰撞面需提供正確的 `angle`、`omega`、`vx`、`vs`。裝飾不可另畫未定義碰撞的低矮擋板。

### 樓梯與沙漏的局部 3D 模型

`overtime-stairs` 的機關主體由 `src/overtime-geometry.js` 共用幾何，`src/overtime-motion.js` 執行接觸解算，元件的 `decorate`／`update` 使用相同尺寸與高度繪圖。每個 90 Hz 固定步內執行 4 次子步，以 `g = 9.81 m/s²` 更新球的位置與三軸速度，解決移動斜頂、實心階梯立面、平台導欄、靜止上下漏斗、主賽道路面及 3D 空間雜湊球間接觸。球離開漏斗後自由落下，落地保留動量；`stage` 只觀察目前所在區域，不能驅動位置、轉圈秒數或定時放行。主賽道仍使用原有的賽道約束滾動模型。

階梯 `amplitude` 經 2.2 的機械傳動比放大；為限制馬達加速度不超過 `4.4 m/s²`，有效週期為 `max(period, 2π × sqrt(amplitude × 2.2 / 4.4))`。修改繪圖或物理時均須使用共享的 `stairHeight`、`stairVelocity` 與有效週期，不能直接拿要求的 `period` 畫動畫。舊存檔的 `orbit` 數字保留相容，v6 用來調整漏斗接觸摩擦：數值愈大，阻力愈小；實際停留時間由運動與碰撞決定。

修改本機關後，執行 `node --test tests/overtime-stairs.test.js tests/overtime-visuals.test.js tests/replay.test.js`，並以完整測試及大量參賽者賽事確認全員可通行。幾何測試應檢查各相位階梯頂面與固定底座、平台斜度、導流欄端點，以及上下漏斗的半徑與世界高度；物理測試應檢查速度傳遞、重力落下、球間碰撞及種子可重現性。GPU 瀏覽器中的穿透、鏡頭及投影可讀性需另行檢查。

新賽事使用 `banyan-constrained-rolling-v7`；舊 v1 至 v6 紀錄由各自凍結的舊引擎重播，v6 完整保留在 `src/legacy/v6/`。現行賽事略過已下架的舊機關。畫面讀取同一份機關狀態；得獎順序仍以實際過線決定。下載的賽事紀錄包含賽道配置、物理版本與種子，重播使用紀錄快照：

```sh
node scripts/replay.mjs "賽事紀錄-種子.json"
```

更改機關物理行為時須保留舊版引擎並提升 `MODEL_VERSION`，設定快照不能取代舊版物理程式碼。

## GitHub Pages 純靜態部署

不需要後端、資料庫或 API 金鑰。`npm ci` 後執行 `npm run build`，發布 `dist/` 即可。Vite 使用相對資源路徑，支援 GitHub Pages 專案子路徑與自訂網域。Pages 工作流程會在 `main` 更新時建置發布；賽道、名單與得獎紀錄仍保存在各訪客瀏覽器。

## v7 封閉匯集道與出口

預設漏斗半徑為 7、喉口半徑 .56；匯集道寬 1.68、窄道長 6.8。`deckPolygons`、`guides` 和 `guardTop` 同時供繪圖與物理使用，窄道護欄在外緣接合，頂蓋連續銜接階梯、匯集道與漏斗。只有實際通過中央喉口再落地才放行，外緣接觸不會結束機關狀態。喉口的旋轉銷使用 `throatSweeper` 位置與表面速度解接觸，防止多球拱橋永遠封住出口。
